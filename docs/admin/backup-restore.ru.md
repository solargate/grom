# Резервное копирование и восстановление

Резервная копия сервера включает метаданные и файлы: треки, фотографии, аватары и ключи. Сохраняйте их на один момент времени.

## Создание резервной копии {#backup}

1. Остановите Grom, чтобы тренировки и задания импорта не меняли данные во время копирования. Запишите версию Grom и пути, которые использует служба.
2. Скопируйте файл конфигурации и весь каталог, на который указывает `storage.location`. В нём находятся файлы обоих драйверов, ключи федерации и пара ключей VAPID для push-уведомлений.
3. Для `bbolt` также скопируйте БД, если `storage.bbolt.path` указывает за пределы `storage.location`. По умолчанию файл `grom.db` находится внутри этого каталога. Если используется статический TLS, включите в копию сертификат и закрытый ключ, указанные в конфигурации.
4. Храните копию в защищённом месте. В ней есть личные данные тренировок и секреты. После копирования снова запустите Grom.

Если `storage.temp_dir` находится отдельно от каталога данных, временные загрузки Strava можно оставить за пределами копии. После прерывания импорта пользователи могут загрузить тот же архив повторно.

## Восстановление {#restore}

1. Остановите Grom и сохраните отдельную копию текущих данных перед их заменой.
2. Восстановите конфигурацию, каталог данных и внешние файлы БД или TLS из одной резервной копии. Для первого запуска используйте прежнюю версию Grom. Сохраните драйвер хранилища, имя хоста федерации и права доступа к файлам. Если изменился каталог бинарника, проверьте, куда теперь указывают относительные пути.
3. Запустите Grom с восстановленной конфигурацией. Войдите, откройте список тренировок и тренировку с треком и фотографиями. Проверьте трек и вложения. По возможности заранее проверьте восстановление в отдельной среде.

Настройки драйверов и порядок миграции описаны в разделе [«Конфигурация»](configuration.md#storage-drivers).

# Одобренные серверы Grom {#approved-grom-servers}

Android-приложение может подключиться к **любому** инстансу Grom: введите URL сервера при входе, регистрации или сбросе пароля. Можно также выбрать сервер из списка **одобренных публичных инстансов**, вшитого в приложение, плюс серверы, которыми вы уже пользовались.

Эта страница для:

- тех, кто в Android хочет выбрать публичный инстанс
- операторов, которые хотят, чтобы их публичный инстанс появился в этом списке

Попадание в список **не означает** одобрения политики конфиденциальности или аптайма оператора. У Grom нет центрального облака: вы сами выбираете, на каком сервере живёт аккаунт. См. [Privacy Policy](../privacy.md).

## В Android-приложении {#in-the-android-app}

На экранах **Вход**, **Регистрация** и **Сброс пароля** у поля URL сервера есть кнопка выпадающего списка.

- **Одобренные серверы** берутся из каталога, вкомпилированного в эту версию приложения: URL (жирным), имя и короткое описание.
- **Недавние серверы** — URL, которые вы ввели сами и после этого **успешно вошли или зарегистрировались**. Они показываются под одобренными. Сброс пароля в этот список не добавляет. Удалить запись нельзя; старые вытесняются после многих других успешных подключений.
- По-прежнему можно ввести любой хост или URL (схема необязательна). HTTP разрешён для локальных / LAN-инстансов. Как клиент проверяет HTTPS и HTTP — в [Обзоре для пользователя](overview.md).

Каталог **вшит в APK**. Правка файла в git не обновляет уже установленные приложения; новые записи появятся после установки Android-релиза с этим изменением.

## Добавить свой инстанс (pull request) {#add-your-instance-pull-request}

Любой может открыть pull request к [`server-catalog.yaml`](https://github.com/solargate/grom/blob/master/server-catalog.yaml) в корне репозитория.

1. Сделайте форк [solargate/grom](https://github.com/solargate/grom) и ветку.
2. Добавьте **одну** запись в `servers:` (не удаляйте и не переписывайте чужие инстансы).
3. Откройте pull request в `master`. Мейнтейнер его проревьюит.

Пример:

```yaml
servers:
  - url: https://grom.example.org
    name: Example Grom
    description: Public instance for testing federation.
    email: admin@example.org
```

### Поля {#fields}

| Поле | В приложении | Правила |
|------|----------------|--------|
| `url` | Да (жирным) | Должен начинаться с `https://`. **Без порта** (даже `:443`). Путь разрешён (`https://host/grom`). Без userinfo, query и fragment. Хост — DNS-имя, не IP. |
| `name` | Да | Короткое имя, не больше 80 символов. Один язык — как напишете. |
| `description` | Да (мелким шрифтом) | Одно-два предложения, не больше 280 символов. Один язык — как напишете. |
| `email` | Нет | Контакт оператора для ревью. Должен содержать `@`. |

CI отклоняет невалидный YAML (нет `https://`, порты, дубликаты после нормализации завершающих `/` и т. п.). Мейнтейнер может также отклонить запись, если это не публичный инстанс Grom, сломан TLS или описание выглядит вводящим в заблуждение.

После merge инстанс попадёт в **следующий Android-релиз**. Если в том же изменении нужно обновить сгенерированный Flutter-файл, выполните `make catalog`; CI упадёт, если файл устарел.

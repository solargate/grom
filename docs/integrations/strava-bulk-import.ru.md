# Массовый импорт Strava

Документ описывает, как Grom импортирует тренировки из ZIP [массового экспорта данных Strava](https://support.strava.com/hc/en-us/articles/216918437-Exporting-your-Data-and-Bulk-Export).

## Обзор

1. Пользователь загружает ZIP экспорта Strava на странице **Integration → Strava**.
2. Архив сохраняется в `{storage.temp_dir}/{nickname}/`.
3. Сервер открывает ZIP через Go `archive/zip` и читает файлы напрямую (полной распаковки нет).
4. Для каждой активности Grom создаёт YAML тренировки, при необходимости прикрепляет трек (`AttachTrack`), фото и снаряжение.
5. После завершения временный каталог импорта пользователя удаляется.

## Конфигурация

```yaml
storage:
  temp_dir: tmp
```

По умолчанию: `tmp` (относительно бинарника grom, как `storage.location`).

| 3 | Название тренировки | `name` | |

Игнорируемые колонки включают col 7 (локализованная дистанция в км) — вместо неё col 18 (метры).

## Обработка трека: `AttachTrack` vs `CreateWithTrack`

| Метод | Сценарий | Перезаписывает метрики CSV |
|-------|----------|----------------------------|
| `CreateWithTrack` | Ручная загрузка тренировки в UI | Да (`start_date`, `duration_seconds`, `distance`) |
| `AttachTrack` | Импорт Strava | **Нет** — значения CSV сохраняются |

`AttachTrack` всё равно пишет файл трека, задаёт `device` из FIT при наличии и генерирует `map-preview.webp`, если есть GPS-данные.

## Снаряжение

В `activities.csv` (col 12) хранится отображаемое имя снаряжения, а в `bikes.csv` и
`shoes.csv` части имени лежат в разных колонках (col 1 = прозвище, col 2 = марка,
col 3 = модель). Колонка с прозвищем пуста, если у снаряжения нет своего названия,
поэтому Grom сопоставляет все комбинации этих частей, а не только прозвище.

1. Сопоставить имя снаряжения активности (col 12) с уже существующим снаряжением пользователя.
2. Если не найдено — искать в `bikes.csv` → создать `bike`.
3. Иначе искать в `shoes.csv` → создать `shoes`.
4. Иначе создать снаряжение `other` с данным именем.

Снаряжение из `bikes.csv` / `shoes.csv` создаётся с именем-прозвищем (если оно пустое —
`марка модель`), а также с маркой и моделью.

## Определение локали

Grom определяет локаль экспорта по названиям типов спорта и строкам дат, затем разбирает:

- **Даты** — английские и русские форматы Strava, включая четырёхбуквенные русские сокращения месяцев (`сент.`, `нояб.`, `февр.`).
- **Числа** — десятичный разделитель запятая или точка, разделители тысяч.
- **Булевы** — `true` / `false` (в экспортах Strava не зависят от локали).

## Сопоставление типов спорта

Локализованные названия спорта Strava сопоставляются с ID типов спорта Grom (`Run`, `Ride`, `WeightTraining`, …). Когда Strava экспортирует общий тип вроде `Workout` / `Тренировка`, Grom может вывести более конкретный спорт из названия активности (например `Пилатес (день)` → `Pilates`). Неизвестные типы сводятся к `Workout`.

Результаты импорта включают:

- `parse_skipped` — строки из `activities.csv`, которые не удалось разобрать (например неверные даты) и которые не импортированы
- `media_missing` — пути фото из колонки media CSV, которых не было в ZIP (массовый экспорт Strava часто опускает старые медиа; видео игнорируются и не считаются)

## API

| Method | Path | Описание |
|--------|------|----------|
| `POST` | `/api/v1/integrations/strava/import` | Загрузка ZIP (поле `archive`), ответ `202` |
| `GET` | `/api/v1/integrations/strava/import/status` | Прогресс загрузки/импорта |

## Повторный импорт

Если у пользователя уже есть тренировка с тем же `external_id` (`name` = `strava` и совпадающий `id`), активность пропускается.
